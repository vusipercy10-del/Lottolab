# Pool Building

## Primary pool
Use the highest-scoring candidates after all filters.

## Core pool
Numbers appearing strongly across multiple independent modules:
frequency + mathematical category + multiple overlap + ending/transition.

## Alternative pool
Candidates that are structurally strong but not in the primary pool.

## Reserve pool
Candidates kept for diversification and backtest comparison.

## Overlap
An overlap number is one that appears in two or more independently generated pools. Treat overlap as a ranking feature, not proof of future occurrence.

## Rotation
Build tickets with different Core/Alternative/Reserve proportions instead of repeating one exact ticket.

## Example 3/15 structure
- 1–2 primes
- balanced odd/even
- mixed ending digits
- at least one multiple-overlap candidate where supported by the data
- avoid forcing a pattern solely because it appeared recently
